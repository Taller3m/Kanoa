FEATURE 1- GESTIÓN DE USUARIOS
HUPW-001 – Crear usuario con rol Comunicador (Portal Web) 
Como 
Superadministrador del LMS 
Quiero 
Crear usuarios con rol Comunicador desde la sección del Portal Web 
Para 
Permitir la gestión y actualización del contenido del portal institucional por parte de usuarios autorizados 
 
Descripción 
Esta historia permite al Superadministrador crear usuarios con rol Comunicador desde el módulo del Portal Web dentro del LMS. 
El flujo inicia cuando el Superadmin accede a su cuenta, navega a la sección del Portal Web y selecciona la opción de creación de usuario Comunicador. El sistema despliega un menú lateral con un formulario que solicita los datos personales, de contacto y ubicación. 
Una vez diligenciada la información, el sistema muestra una pantalla resumen para confirmación antes de la creación del usuario. 
En el flujo de creación, el Superadministrador podrá: 
Ingresar nombres y apellidos 
Seleccionar tipo de documento 
Registrar número de documento 
Ingresar fecha de nacimiento (validando mayoría de edad) 
Registrar celular con indicativo internacional 
Ingresar correo electrónico 
Visualizar el rol preconfigurado como "Comunicador" 
Ingresar nombre de usuario (opcional) 
Cargar foto (opcional) 
Registrar datos de ubicación (departamento y municipio) 
Ingresar dirección (opcional) 
 
El sistema debe: 
Validar todos los campos obligatorios 
Garantizar unicidad de correo y documento 
Validar reglas de formato y restricciones de campos 
Mostrar pantalla resumen antes de confirmar 
Crear el usuario y listarlo en el módulo de Comunicadores
Crear la contraseña de forma automática según las condiciones definidas 
Enviar notificación por correo indicando que el usuario fue creado

Restricciones clave del proceso 
Solo el Superadministrador puede crear usuarios Comunicadores 
El rol se asigna automáticamente como Comunicador (no editable) 
El correo electrónico debe ser único en el sistema 
El número de documento no puede repetirse 
La persona debe ser mayor de 18 años 
Se permiten múltiples usuarios con rol Comunicador activos simultáneamente 
La contraseña debe cumplir políticas de seguridad 
Los campos no deben contener espacios iniciales o finales 
No se permiten múltiples espacios consecutivos en campos de texto


Criterios de Aceptación 
Escenario 1: Acceso a creación de usuario Comunicador 
Dado que el Superadmin ha iniciado sesión en el LMS Cuando ingresa a la sección Portal Web Y selecciona la opción “Crear usuario Comunicador” Entonces el sistema debe desplegar el formulario en un menú lateral 
 
Escenario 2: Visualización del rol preasignado 
Dado que el formulario de creación está visible Cuando el Superadmin visualiza el campo Rol Entonces el sistema debe mostrar “Comunicador” como valor por defecto Y no debe permitir su edición 
 
Escenario 3: Validación de campos obligatorios 
Dado que el Superadmin deja campos obligatorios vacíos Cuando intenta continuar Entonces el sistema debe impedir el avance Y mostrar el mensaje: “La información de este campo es obligatoria.” 
 
Escenario 4: Validación de nombres y apellidos 
Dado que el Superadmin ingresa nombres o apellidos Cuando el texto tiene menos de 3 caracteres o contiene espacios al inicio o final Entonces el sistema debe mostrar error de validación con el mensaje que corresponda: “La información ingresada en este campo debe contener al menos 3 caracteres” o “La información ingresada en este campo no puede comenzar ni terminar con espacios” Y no permitir continuar. 
 
Escenario 5: Validación de documento 
Dado que el Superadmin ingresa el número de documento Cuando el valor contiene caracteres no numéricos, espacios inválidos o está duplicado Entonces el sistema debe mostrar: “La información ingresada es inválida, este campo solo debe contener números” “El número de documento ingresado ya existe” 
 
Escenario 6: Validación de fecha de nacimiento 
Dado que el Superadmin ingresa la fecha de nacimiento Cuando la persona es menor de 18 años o el formato es inválido Entonces el sistema debe mostrar: “Fecha de nacimiento inválida. Asegúrate de ingresar una fecha que corresponda a una persona mayor de 18 años.” 
 
Escenario 7: Validación de celular 
Dado que el Superadmin ingresa el celular Cuando no cumple el formato internacional o tiene menos de 10 dígitos Entonces el sistema debe mostrar mensaje de error “El número de celular ingresado es inválido. Debe contener al menos 10 dígitos, incluyendo el código de país”  
 
Escenario 8: Validación de correo electrónico 
Dado que el Superadmin ingresa el correo Cuando el formato es inválido o ya existe en el sistema en estado “Activo” Entonces el sistema debe mostrar el mensaje correspondiente: “Por favor, ingresa una dirección de correo electrónico válida” o “El correo electrónico ya se existe. Por favor, elija un correo único” 
Nota: si el correo ya existe, pero se encuentra asociado a un usuario inactivo si se debe permitir crear otro usuario con el mismo correo. 
 
Escenario 9: Visualización de pantalla resumen 
Dado que el formulario está completo y válido Cuando el Superadmin continúa el proceso Entonces el sistema debe mostrar un resumen con la información ingresada 
 
Escenario 10: Creación exitosa del usuario 
Dado que el Superadmin confirma la información Cuando selecciona “Crear usuario” Entonces el sistema debe crear el usuario  Y mostrar el mensaje de confirmación “Usuario Comunicador creado Exitosamente” Y agregarlo a la lista de usuarios Comunicadores Y generar la contraseña automáticamente según las reglas definidasY enviar un correo informando su creación 
 
Escenario 11: Cancelación del proceso 
Dado que el Superadmin inicia la creación Cuando decide cancelar Entonces el sistema debe solicitar confirmación Y si confirma, cerrar el formulario sin guardar 
 
Historia(s) de Usuario Relacionada(s) 
HU-PW-006 – Generación correo con datos de acceso usuario comunicador   


Notas y Soportes Adicionales 
El campo “Nombre de usuario” y “Foto” podrán actualizarse posteriormente en el módulo de configuración de cuenta 
El sistema debe mostrar separador de miles en el número de documento (visual) sin afectar almacenamiento 
El flujo incluye pantalla resumen previa a la confirmación 
Se deben permitir múltiples usuarios con rol Comunicador activos simultáneamente 

Reglas de Validación 
Nombres y apellidos: mínimo 3 caracteres, sin espacios iniciales o finales 
Documento: numérico, único, sin espacios inválidos 
Fecha nacimiento: formato válido, mayor de 18 años 
Celular: mínimo 10 dígitos, con indicativo (+) 
Correo: formato válido y único 
Contraseña:  
Mínimo 8 caracteres 
Máximo 20 
1 carácter especial 
1 mayúscula 
1 número Nota: la contraseña se generará automáticamente por el sistema no se debe incluir dentro del formulario de creación de usuario. 
Departamento y municipio: obligatorios 
Dirección: opcional 
Nombre de usuario: opcional, único 
Foto: opcional (máx. 5 MB) 

Ayuda / Tooltip 
“La contraseña debe tener entre 8 y 20 caracteres, incluyendo al menos una mayúscula, un número y un carácter especial.” 
“Después del signo +, ingresa el indicativo del país seguido del número de celular.” 


HU-PW002 – Edición de usuario Comunicador
Como:
Superadministrador del LMS
Quiero:
Editar los datos de un usuario con rol Comunicador previamente creado
Para:
Corregir o actualizar la información registrada y asegurar que esté completa y válida

Descripción
Una vez creado el usuario con rol Comunicador, el Superadministrador podrá acceder al perfil del usuario desde la sección del Portal Web y editar todos los campos disponibles excepto el correo electrónico, el cual debe permanecer bloqueado por ser un identificador único dentro del sistema. El sistema debe aplicar las mismas reglas de negocio definidas para la creación, validar los datos ingresados y mostrar mensajes claros de advertencia y éxito. La edición debe quedar registrada con trazabilidad (fecha y usuario que realizó el cambio).

Criterios de Aceptación 
Escenario 1: Edición exitosa del usuario Comunicador 
Dado que el Superadmin accede al perfil de un usuario Comunicador Y modifica uno o varios campos válidos Cuando confirma la edición Entonces el sistema guarda los cambios Y muestra el mensaje: “La información ha sido actualizada correctamente.” Y registra la fecha de modificación y el usuario que realizó el cambio 
Escenario 2: Campo bloqueado para edición (correo electrónico) 
Dado que el Superadmin accede al formulario de edición del usuario Cuando visualiza el campo de correo electrónico Entonces el sistema muestra el campo como bloqueado Y no permite modificar su contenido 
Escenario 3: Validación de campos obligatorios y errores de formato 
Dado que el Superadmin modifica campos con datos incompletos o incorrectos Cuando intenta guardar los cambios Entonces el sistema no habilita el botón de guardar Y muestra los siguientes mensajes según corresponda: 
“La información de este campo es obligatoria.” 
“La información ingresada en este campo debe contener al menos 3 caracteres.” 
“La información ingresada en este campo no puede comenzar ni terminar con espacios.” 
"El número de documento ingresado ya existe.” 
“La información ingresada es inválida, este campo solo debe contener números." 
“La información que ingresaste excede el límite máximo de caracteres permitidos.” 
“Fecha de nacimiento inválida. Asegúrate de ingresar una fecha que corresponda a una persona mayor de 18 años.” 
“El número de celular ingresado es inválido. Debe contener al menos 10 dígitos, incluyendo el código de país.” 

Escenario 4: Validación de duplicidad de documento 
Dado que el Superadmin modifica el número de documento Cuando ingresa un número que ya existe en el sistema Entonces el sistema muestra el mensaje: “El número de documento ingresado ya existe.” Y no permite guardar los cambios 
Escenario 5: Cancelación del proceso de edición 
Dado que el Superadmin desea cancelar la edición del usuario Cuando presiona el botón “Cancelar” Entonces el sistema muestra el mensaje de confirmación: “¿Estás seguro de que deseas cancelar la edición del usuario?” Y si selecciona “Salir sin guardar”, se cierra el formulario sin guardar información Y el sistema quita el panel de edición y vuelve a la pantalla de visualización de detalle del usuario.
 
Corner Cases 
Intento de editar el usuario sin modificar ningún campo: no se habilita el botón de Guardar 
Modificación del número de documento a uno existente en otro usuario: no permite guardar y muestra el mensaje ya definido
Ingreso de valores con espacios en blanco al inicio o final: no permite guardar y muestra el mensaje ya definido
Uso de caracteres no permitidos en campos alfabéticos o numéricos: no permite guardar y muestra el mensaje ya definido
Fecha de nacimiento exactamente en el límite de 18 años: la fecha de nacimiento debe corresponder mínimo a una fecha de hace 18 años a partir del momento en el que se realiza el registro
Cambio de datos válidos a inválidos durante la edición: no permite guardar y muestra el mensaje ya definido
Cancelación del proceso después de haber realizado múltiples cambios: no se generan cambios en la información inicial 
Interrupción del proceso (por cierre de sesión o caída de conexión) antes de guardar: no se generan cambios en la información inicial
Campos opcionales eliminados o vacíos tras haber tenido información previa: se genera la actualización exitosamente
Carga de imagen que excede el tamaño permitido: mostrar mensaje correspondiente según diccionario de datos
Historia de Usuario Relacionada 
HUPW-001 – Crear usuario con rol Comunicador (Portal Web) 

Notas y Soportes Adicionales 
Las reglas de negocio aplicadas en la creación deben mantenerse en la edición. 
El sistema debe registrar la trazabilidad de la modificación (usuario y fecha). 
El campo correo electrónico es único y no editable. 
El sistema debe mantener la consistencia de validaciones definidas para el rol Comunicador.
HU-PW-003 – Grilla-Visualización de usuarios Comunicadores
Como:
Superadministrador del LMS
Quiero:
Visualizar el listado de usuarios con rol Comunicador
Para:
Consultar, ubicar y gestionar los usuarios encargados del contenido del Portal Web

Descripción
Desde la sección del Portal Web dentro del LMS, el Superadministrador podrá visualizar un listado de todos los usuarios con rol Comunicador registrados en el sistema.
El listado deberá presentarse de forma paginada para facilitar la navegación entre registros y optimizar la visualización de grandes volúmenes de información.
Adicionalmente, el sistema debe proporcionar un campo de búsqueda que permita filtrar los usuarios en tiempo real, tomando como referencia los campos de nombre y correo electrónico. La búsqueda debe ser flexible, ignorando diferencias entre mayúsculas, minúsculas y tildes.

Criterios de Aceptación (Gherkin)
Escenario 1: Visualización mensaje Inicial sin usuarios aun creados
Dado que el Superadmin accede a la sección del Portal Web Cuando ingresa al módulo de usuarios Comunicadores y aun no se ha creado el primer usuario comunicador Entonces el sistema debe mostrar un mensaje que invite al usuario a crear el primer usuario comunicador (ver diseños y diccionario de datos)

Escenario 2: Visualización del listado de usuarios Comunicadores
Dado que el Superadmin accede a la sección del Portal Web Cuando ingresa al módulo de usuarios Comunicadores Entonces el sistema debe mostrar un listado con los usuarios creados Y cada registro debe incluir información básica del usuario Y debe mostrarse de forma paginada

Escenario 3: Paginación del listado
Dado que existen múltiples usuarios Comunicadores registrados Cuando el listado excede el número máximo de registros por página Entonces el sistema debe dividir la información en páginas (50 usuarios por página) Y permitir navegar entre ellas (siguiente, anterior o selección de página)

Escenario 4: Búsqueda con coincidencias
Dado que soy un super administrador Cuando ingreso al menos una letra en el campo de búsqueda de usuarios Entonces el sistema deberá buscar coincidencias en los campos Nombre y Correo Y deberá ignorar diferencias entre mayúsculas, minúsculas o tildes Y se mostrará una lista con todos los usuarios que coincidan con el criterio de búsqueda

Escenario 5: Búsqueda sin coincidencias
Dado que soy un Super administrador Cuando ingreso un valor que no tiene coincidencias con ningún usuario Entonces el sistema mostrará el mensaje: “No se encontraron resultados para tu búsqueda”

Escenario 6: Actualización del filtro de búsqueda
Dado que realicé una búsqueda anterior Cuando modifique el valor del campo de texto Entonces el sistema actualizará automáticamente la lista de usuarios en función del nuevo texto ingresado Y eliminará los resultados anteriores si ya no coinciden

Escenario 7: Estado inicial del buscador
Dado que el Superadmin accede al listado de usuarios Cuando no ha ingresado ningún criterio de búsqueda Entonces el sistema debe mostrar todos los usuarios disponibles Y aplicar la paginación por defecto

Historia de Usuario Relacionada
HUPW-001 – Crear usuario con rol Comunicador (Portal Web)HU-PW-002 – Edición de usuario Comunicador 

Notas y Soportes Adicionales
El listado debe cargarse de forma eficiente para garantizar tiempos de respuesta óptimos.
La búsqueda debe ejecutarse en tiempo real o con un pequeño retardo controlado (debounce).
La paginación debe mantener consistencia con los filtros activos.
El sistema debe preservar el estado de búsqueda al navegar entre páginas.
Los mensajes deben seguir los lineamientos definidos en el diccionario de datos: Diccionario de datos.xlsx

Corner Cases
Búsqueda con espacios en blanco al inicio o final
Búsqueda con caracteres especiales o tildes
Ingreso de una sola letra que genere múltiples coincidencias
Eliminación completa del texto de búsqueda después de filtrar
Navegación entre páginas con un filtro activo
Cambio de página cuando ya no hay resultados disponibles
Usuarios con nombres muy similares o correos casi iguales
Listado vacío cuando no existen usuarios Comunicadores
Fallo en la carga de datos del listado
Cambios en los datos (edición/eliminación) mientras el usuario está navegando el listado



HU-PW-004 – Cambiar estado Activar/Inactivar usuario comunicador

Como:
Superadministrador del LMS
Quiero:
Activar o inactivar usuarios comunicadores
Para:
Controlar el acceso al sistema y la gestión de contenido del portal

Descripción
Dentro del módulo de administración de usuarios, el Superadministrador podrá cambiar el estado de un usuario comunicador desde la grilla. Esta acción impacta directamente la autenticación del usuario en el portal.

Criterios de Aceptación Escenario 1: Confirmar Inactivar usuario 
Dado que el Superadmin se encuentra en la grilla de usuarios comunicadores  Y el usuario tiene estado "Activo" Cuando selecciona la opción "Inactivar" Entonces el sistema muestra un mensaje de confirmación “¿Estás seguro que deseas inactivar al usuario? Recuerda que no tendrá acceso al sistema” Y Cuando el Superadmin confirma la acción Entonces el sistema cambia el estado a "Inactivo" del usuario comunicador Y el usuario no podrá acceder al portal Y se muestra el mensaje "El usuario ha sido inactivado exitosamente y no tendrá acceso al sistema" 
 
Escenario 2: Cancelar Inactivar usuario 
Dado que el Superadmin se encuentra en la grilla de usuarios comunicadores  Y el usuario tiene estado "Activo" Cuando selecciona la opción "Inactivar" Entonces el sistema muestra un mensaje de confirmación "Estás seguro que deseas inactivar al usuario? Recuerda que no tendrá acceso al sistema” Y Cuando el Superadmin cancela la acción Entonces el sistema conserva el estado " Activo " del usuario comunicador Y no se evidencian cambios de estado en la grilla Y el usuario comunicador puede seguir accediendo al portal 

Escenario 3: Intento de Activar Usuario Inactivo con correo duplicado
Dado que el usuario comunicador está en estado "Inactivo" en la grilla Cuando el Superadmin selecciona la opción "Activar" Entonces el sistema valida que el usuario a Activar no tenga otro usuario registrado en el sistema, en estado Activo y que tenga el mismo correo asociado.Y en caso de presentarse este caso se debe mostrar el mensaje "El usuario que intenta activar ya tiene otro usuario activo con el mismo correo asociado"

Escenario 4: Confirmar Activar Usuario 
Dado que el usuario comunicador está en estado "Inactivo" en la grilla Cuando el Superadmin selecciona la opción "Activar" Entonces el sistema muestra un mensaje de confirmación ¿Estás seguro que deseas activar al usuario? Y Cuando el Superadmin confirma la acción Entonces el sistema cambia el estado a "Activo" del usuario comunicador Y el usuario puede autenticarse en el portal  Y se muestra el mensaje " El usuario ha sido activado exitosamente y puede acceder al sistema. 
 Escenario 5: Cancelar Activar Usuario 
Dado que el usuario comunicador está en estado "Inactivo" en la grilla Cuando el Superadmin selecciona la opción "Activar" Entonces el sistema muestra un mensaje de confirmación ¿Estás seguro que deseas activar al usuario? Y Cuando el Superadmin cancela la acción Entonces el sistema conserva el estado " Inactivo " del usuario comunicador Y no se evidencian cambios de estado en la grilla Y el usuario comunicador No puede acceder al portal 
 
Escenario 6: Error en actualización 
Dado que se puede presentar algún error en el sistema en el momento de ejecutar alguna de las acciones descritas en los criterios anteriores Cuando ocurre un error en el sistema  Entonces se muestra "No fue posible actualizar el estado del usuario, intente nuevamente"

HU-PW-007 – Gestión de restablecimiento de contraseña de usuarios por SuperAdmin 

Como:
Usuario Super Administrador (SuperAdmin)
Quiero:
Cambiar la contraseña de los usuarios del sistema
Para:
Gestionar el acceso de los usuarios y garantizar la recuperación y seguridad de sus cuentas

Descripción
El Super Administrador podrá cambiar la contraseña de los usuarios comunicadores desde el módulo administrativo del LMS. Esta acción permitirá:
Recuperar accesos en caso de olvido de contraseña
Forzar el cambio de credenciales por seguridad
Garantizar el control administrativo sobre los accesos

Criterios de Aceptación 
Escenario 1: Opción Cambiar Contraseña desde el SuperAdmin
Dado que el SuperAdmin ha iniciado sesión en el LMS Cuando accede a la grilla de usuarios del rol al que quiere realizar el cambio y selecciona un usuarioEntonces el sistema debe mostrar la opción “Restablecer contraseña” dentro del detalle del usuario

Escenario 2: Confirmación nueva contraseña no coincide 
Dado que el usuari SuperAdmin  se encuentra dentro de la opción de “CAMBIAR CONTRASEÑA” 
Cuando ingresa la confirmación de la nueva contraseña y no coincide 
Entonces se muestra el mensaje: “Las contraseñas no coinciden.”

Escenario 3: Confirmación de cambio de contraseña
Dado que el SuperAdmin selecciona la opción “CAMBIAR CONTRASEÑA”Cuando ingresa una contraseña nueva válida y le da clic en “Actualizar”Entonces se debe mostrar el mensaje: “Contraseña Actualizada. La contraseña ha sido actualizada correctamente”
Escenario 4: Validaciones de contraseña
Dado que el usuario SuperAdmin cambia la contraseña para otro usuarioCuando ingresa la contraseña nuevaEntonces debe cumplir las siguientes reglas:
Mínimo 8 caracteres 
Máximo 20 
1 carácter especial 
1 mayúscula 
1 número
Escenario 5: Error en el proceso
Dado que ocurre un error al cambiar la contraseñaCuando el SuperAdmin ejecuta la acciónEntonces el sistema debe mostrar el mensaje: “No fue posible restablecer la contraseña. Intenta nuevamente”
Ayuda / Tooltip 
“La contraseña debe tener entre 8 y 20 caracteres, incluyendo al menos una mayúscula, un número y un carácter especial.”


HU-PW-008 – Generación correo con confirmación de Activación de Usuario Comunicador
Como:
Superadministrador del LMS
Quiero:
Generar y enviar un correo de confirmación cuando se active un usuario comunicador
Para:

Valor
Permitir la administración de la información principal del Hero para comunicar mensajes estratégicos, promover contenidos relevantes y facilitar la navegación de los usuarios dentro del Portal WEB.

HU-PW-090 – Configurar destacados del Hero
Como:
Usuario Comunicador autenticado en el módulo administrativo del Portal WEB
Quiero:
Configurar los elementos destacados que se visualizarán en el Hero principal de la página de inicio
Para:
Promover contenidos estratégicos y facilitar el acceso de los usuarios a micrositios y secciones relevantes del Portal WEB
Descripción
El sistema debe permitir al usuario Comunicador configurar los elementos destacados que se mostrarán en el bloque derecho del Hero principal del Home.
La visualización de destacados será opcional y estará controlada mediante un interruptor (booleano):
Mostrar destacados
Activado
Desactivado
Cuando la opción se encuentre activada, el sistema deberá permitir configurar exactamente tres (3) elementos destacados.
Cada destacado corresponderá a una posición fija dentro del Hero:
Destacado 1
Destacado 2
Destacado 3
Cada posición permitirá seleccionar un único elemento.
Los elementos disponibles para selección podrán ser:
Micrositios activos.
Secciones activas.
La selección podrá combinar micrositios y secciones libremente.
La información disponible deberá actualizarse dinámicamente teniendo en cuenta:
Activación/Inactivación de micrositios.
Activación/Inactivación de secciones.
Actualización de nombres de micrositios.
Actualización de nombres de secciones.
Cuando la opción Mostrar destacados se encuentre desactivada, no será obligatorio seleccionar elementos destacados.
La configuración de destacados comparte la misma pantalla administrativa utilizada para configurar el contenido principal del Hero y utiliza el mismo mecanismo de almacenamiento.
Valor
Permitir una promoción flexible de contenidos relevantes dentro del Home, facilitando que el Comunicador destaque micrositios o secciones según las prioridades del negocio.

Reglas de Negocio
Mostrar destacados
Configuración controlada mediante un booleano:
Activado.
Desactivado.
Cuando está activado
Deben configurarse exactamente tres (3) destacados.
Las tres posiciones son obligatorias.
Cuando está desactivado
No se requiere seleccionar destacados.
El bloque de destacados no será mostrado en el Home.

Destacados
El Hero dispone de tres posiciones configurables:
Destacado 1
Destacado 2
Destacado 3
Cada posición:
Permite seleccionar un único elemento.
Puede contener un micrositio o una sección.
Puede modificarse posteriormente.

Elementos disponibles para selección
Micrositios
Únicamente micrositios Activos.
Secciones
Únicamente secciones Activas.
Las listas deberán actualizarse automáticamente según los cambios realizados desde la administración.

Mensajes
Destacados obligatorios
Si el bloque de destacados se encuentra activo y alguna posición no tiene información:
"Debes seleccionar los tres elementos destacados."

Destacado 1
Destacado 2

Escenario 3: Desactivación de destacados

Cuando el usuario desactiva la opción Destacados
Entonces el sistema deshabilita la configuración de destacados
Y deja de exigir información en las posiciones configuradas.
Escenario 4: Carga de elementos disponibles
Dado que existen micrositios y secciones configuradas en el Portal WEB
Cuando el usuario selecciona una posición de destacado
Entonces el sistema muestra para selección:
Micrositios activos.
Secciones activas.
Y no muestra elementos inactivos.

Escenario 6: Un único elemento por posición
Dado que una posición ya tiene un elemento seleccionado
Cuando el usuario elige un nuevo elemento
Entonces el sistema reemplaza la selección anterior
Y mantiene una única selección por posición.
Escenario 7: Actualización automática de micrositios

Cuando es activado o inactivado desde la administración

Escenario 8: Actualización automática de secciones

Escenario 11: Cancelación de configuración
Dado que el usuario modifica la configuración de los destacados
Cuando selecciona la opción Cancelar
Entonces el sistema muestra el mensaje:
"Hay cambios sin guardar. ¿Deseas descartarlos?"
Y cuando confirma la acción
Entonces descarta los cambios realizados.

Corner Cases
No existen micrositios ni secciones activas → no existen elementos disponibles para selección.
El nombre de un micrositio cambia → las listas reflejan automáticamente el nuevo nombre.
El nombre de una sección cambia → las listas reflejan automáticamente el nuevo nombre.
El usuario activa Mostrar destacados y configura únicamente una o dos posiciones → no puede continuar con la configuración y muestra el mensaje de error definido.
Un destacado puede ser cambiado cuantas veces sea necesario antes del guardado.
Una misma posición nunca puede contener más de un elemento seleccionado simultáneamente.

Notas y Soportes Adicionales
Persistencia de información
La configuración de destacados forma parte de la misma pantalla utilizada para configurar el contenido principal del Hero.
Por lo tanto:
Existe un único botón Guardar para toda la configuración del Hero.
El almacenamiento se ejecuta de manera unificada.
Esta historia únicamente valida y administra la configuración de destacados.
Mensaje único de éxito de la pantalla Hero
"La configuración del Hero ha sido guardada correctamente."
Dependencia funcional
Los elementos seleccionados como destacados no podrán ser inactivados mientras permanezcan asociados al Hero, según las reglas definidas en:
HU-PW-096 – Restringir la inactivación de elementos destacados configurados en el Hero

HU-PW-088- Visualizar página de inicio con navegación accesible y propuesta de valor

Usuario visitante del Portal WEB KANOA LAB
Quiero:
Visualizar una página de inicio clara y accesible

Comprender rápidamente la propuesta de valor del portal y acceder al contenido que me interesa

El sistema debe permitir que los usuarios visitantes accedan a la página principal (Home) del Portal WEB KANOA LAB.
La página de inicio constituye el principal punto de entrada al portal y debe presentar de manera clara la identidad del portal, su propuesta de valor y los mecanismos de acceso a los diferentes contenidos disponibles.
La estructura, componentes, distribución visual, llamados a la acción y elementos presentes en la página deberán corresponder a los diseños aprobados para el Portal WEB.
Esta historia define la experiencia general de la página de inicio, pero no define el comportamiento individual de los componentes que la conforman, ya que estos serán detallados mediante historias de usuario específicas.
Valor
La página de inicio representa el punto de mayor tráfico del portal y tiene un impacto directo sobre:
La primera impresión de los usuarios.
La percepción de confianza sobre la plataforma.
La comprensión de la propuesta de valor.
La capacidad de los usuarios para encontrar contenido relevante.
La reducción de la tasa de abandono del portal.

Criterios de Aceptación 
Escenario 1: Visualización de la página de inicio
Dado que soy un visitante del portal
Cuando ingreso a la URL principal del Portal WEB

El nombre del portal.
Una propuesta de valor resumida en una frase.
Un llamado a la acción visible.

Dado que la página de inicio ha cargado correctamente
Cuando el usuario visualiza el Home
Entonces el sistema presenta los componentes definidos en los diseños aprobados para la página de inicio
Y permite acceder a las funcionalidades disponibles del portal mediante los componentes correspondientes.
Escenario 4: Navegación accesible
Dado que el usuario interactúa con la página de inicio
Cuando utiliza mecanismos estándar de navegación
Entonces el sistema permite recorrer los elementos interactivos de forma ordenada
Y mantiene una navegación consistente y accesible.

Cuando se registra la visita del usuario
Entonces el sistema emite el evento de página vista
Y registra la fuente de tráfico de origen
Y deja disponible la información para ser consumida por la herramienta de analítica configurada.

Dado que el usuario accede desde diferentes tamaños de pantalla
Cuando visualiza la página de inicio
Entonces el sistema adapta la distribución de los elementos definidos en diseño
Y mantiene la legibilidad y funcionalidad de los componentes.

Dado que el usuario accede a la página de inicio
Cuando la página finaliza su carga

Y mantiene la estructura visual definida en los diseños aprobados.

Usuario ingresa por primera vez al portal → visualiza la propuesta de valor y el llamado a la acción principal.

Usuario navega desde dispositivos móviles → la página adapta su diseño sin pérdida de funcionalidad.
No es posible identificar la fuente de tráfico → el evento de página vista se registra con origen desconocido.
No existe ningún contenido publicado (portal recién lanzado) → el Home debe mostrar las secciones institucionales y un mensaje neutral en los bloques vacíos, nunca un espacio en blanco ni un error.
Un micrositio visible en el Home es deshabilitado desde la administración → su bloque desaparece del Home sin afectar la maquetación de los demás componentes.
Títulos muy largos o muy cortos → deben respetar el comportamiento definido en los diseños aprobados sin romper la estructura visual.
El visitante accede con conexión lenta → los componentes deben mostrar estados de carga definidos por UX sin bloquear la navegación general del Home.

Esta historia define la experiencia general de la página de inicio.
Los comportamientos específicos de cada componente serán documentados en historias independientes.

Su visibilidad en el Portal WEB público
Su disponibilidad para edición y gestión administrativa

Activo
Visible en el Portal WEB público
Permite acceder a la gestión de sus secciones
Permite administrar contenidos asociados
Permite editar información del micrositio
Inactivo
No visible en el Portal WEB público
No permite acceso a la gestión de secciones

No se muestran las secciones asociadas

El estado de los contenidos (HU-PW-016)

FEATURE 6 - GESTIÓN DE MENÚS Y UBICACIONES DE NAVEGACIÓN DEL PORTAL WEB

HU-PW-103 – Administrar menús de navegación
Como:
Usuario Comunicador autenticado en el módulo de Administración de Contenido del Portal WEB
Quiero:
Visualizar y administrar los menús de navegación configurados en el Portal WEB
Para:
Gestionar de forma centralizada las estructuras de navegación que posteriormente podrán utilizarse en las diferentes ubicaciones configurables del portal.

Descripción
El sistema debe incorporar una nueva funcionalidad denominada Menús dentro del módulo administrativo del Portal WEB.
La funcionalidad permitirá al usuario Comunicador administrar los menús de navegación del Portal WEB desde la siguiente ruta: Módulo de Administración de Contenido del Comunicador → Menús.

Al acceder a la pantalla, el sistema deberá mostrar el listado de los menús previamente configurados y las acciones disponibles para su administración.
Esta historia tiene como objetivo administrar los menús existentes y servir como punto de acceso a las funcionalidades de:
Crear menú.
Editar menú.
Eliminar menú.
Gestionar ubicaciones.
La configuración de la estructura interna de los menús, elementos, submenús, enlaces, botones y asignaciones será gestionada en historias posteriores.
Valor
Permitir que el Comunicador administre de manera centralizada los menús del Portal WEB y acceda a las funcionalidades necesarias para configurar la navegación pública del sitio.
Reglas de Negocio
Listado de menús
El sistema deberá mostrar todos los menús configurados.
Cada registro deberá visualizar como mínimo:
Nombre del menú.
Fecha de creación.
Usuario creador.
Fecha de última edición.
Ubicación asignada.
Orden del listado
El listado deberá mostrarse ordenado por: Fecha de última edición desde la más reciente hacia la más antigua.
Menús sin ubicación
Si un menú no tiene una ubicación asignada:
Deberá seguir visualizándose en el listado.
La ubicación deberá mostrarse vacía o con el valor definido por diseño.
El menú no será visible públicamente.
Funcionalidades disponibles
Desde la pantalla de administración de menús deberán existir las siguientes acciones:
Crear menú.
Editar menú.
Eliminar menú.
Gestionar ubicaciones.
Criterios de Aceptación
Escenario 1: Acceso a la administración de menús
Dado que el usuario accede al Módulo de Administración de Contenido del Comunicador
Cuando selecciona la opción Menús
Entonces el sistema muestra la pantalla Administración de menús del Portal WEB.
Escenario 2: Visualización del listado de menús
Dado que existen menús configurados en el sistema
Cuando el usuario accede a la pantalla Administración de menús del Portal WEB
Entonces el sistema muestra el listado de menús disponibles.
Escenario 3: Información visible de cada menú
Dado que el usuario visualiza el listado de menús
Cuando el sistema muestra la información de cada registro
Entonces cada menú presenta como mínimo:
Nombre del menú.
Fecha de creación.
Usuario creador.
Fecha de última edición.
Ubicación asignada.
Escenario 4: Ordenamiento por fecha de última edición
Dado que existen múltiples menús configurados
Cuando el sistema construye el listado
Entonces muestra los menús ordenados por fecha de última edición
Y presenta primero los más recientemente modificados.
Escenario 5: Visualización de menú sin ubicación asignada
Dado que existe un menú sin ubicación asociada
Cuando el usuario visualiza el listado de menús
Entonces el sistema muestra el menú dentro del listado
Y indica que no tiene una ubicación asignada.
Escenario 6: Visualización de opción Crear menú
Dado que el usuario accede a la pantalla Administración de menús del Portal WEB
Cuando visualiza las opciones disponibles
Entonces el sistema muestra la acción:
Crear menú
Y permite acceder a la funcionalidad de creación de menús.
Escenario 7: Visualización de opción Editar menú
Dado que existe un menú registrado
Cuando el usuario visualiza el listado de menús
Entonces el sistema muestra la opción:
Editar menú
para cada registro disponible.
Escenario 8: Visualización de opción Eliminar menú
Dado que existe un menú registrado
Cuando el usuario visualiza el listado de menús
Entonces el sistema muestra la opción:
Eliminar menú 
para cada registro disponible.
Escenario 9: Visualización de opción Gestionar ubicaciones
Dado que el usuario accede a la pantalla Administración de menús del Portal WEB
Cuando visualiza las opciones disponibles
Entonces el sistema muestra la acción:
Gestionar ubicaciones
Y permite acceder a la administración de ubicaciones de navegación.
Escenario 10: Actualización automática del listado
Dado que un menú es creado, editado o eliminado
Cuando el usuario regresa al listado de menús
Entonces el sistema refleja la información actualizada conforme a la última configuración almacenada.
Corner Cases
No existen menús configurados → el sistema muestra el estado vacío definido por diseño.
Existen menús sin ubicación asignada → deben aparecer en el listado.
Existen múltiples menús con diferentes fechas de modificación → se muestran desde el más reciente al más antiguo.
Un menú fue editado recientemente → cambia automáticamente su posición en el listado según el orden definido.
El sistema no puede recuperar la información de los menús → se muestra el mensaje de error correspondiente.

Configuración de elementos.
Asignación de ubicaciones.

Descripción

La pantalla de creación deberá estar compuesta por dos áreas principales:
Panel izquierdo: Elementos disponibles

Los tipos de elementos disponibles serán:
Micrositios activos.
Secciones activas.
Opción personalizada.
Enlace directo.
Botón.

En esta sección el usuario podrá:
Agregar elementos.
Eliminar elementos.
Organizar el orden de los elementos.
Configurar submenús.
Visualizar la estructura final del menú.
Reorganizar la jerarquía mediante drag &amp; drop.
La configuración deberá permitir crear menús simples o menús jerárquicos con múltiples niveles de navegación conforme a los diseños aprobados.
